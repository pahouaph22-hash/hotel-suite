# Saynam Hotel Suite — ระบบหน้าบ้าน + หลังบ้าน

ระบบบริหารโรงแรมที่แยกเป็น 2 ส่วนชัดเจน แต่ใช้ฐานข้อมูลชุดเดียวกัน

| ไฟล์ | ใครใช้ | ทำอะไรได้ |
|---|---|---|
| `index.html` | แขก / ลูกค้า | ดูข้อมูลโรงแรม ห้องพัก ราคา สิ่งอำนวยความสะดวก นโยบาย · ค้นหาห้องว่าง · จอง 4 ขั้นตอน · ชำระมัดจำผ่าน QR · ตรวจสอบการจองด้วยรหัส + เบอร์โทร |
| `admin.html` | พนักงาน | ล็อกอินตามตำแหน่ง · ผังห้องพัก · การจอง · ตรวจเงินมัดจำที่ลูกค้าโอน · ลูกค้า · ห้องพักและแม่บ้าน · ห้องและราคา · ช่องทางขาย · บัญชี IFRS · ประวัติการใช้งาน · ตั้งค่า |
| `config.js` | ผู้ดูแลระบบ | ใส่ Supabase URL + key ที่เดียว ทั้งสองหน้าจะใช้ฐานข้อมูลเดียวกัน |
| `sql/01–03` | ผู้ดูแลระบบ | โครงสร้างฐานข้อมูล กฎการลงบัญชี สิทธิ์ และข้อมูลเริ่มต้น |

ภาษา: ລາວ / ไทย / English ทั้งสองหน้า · สกุลเงิน LAK · VAT ตั้งค่าได้ (ค่าเริ่มต้น 10%)

## 1. ลองใช้ทันที (โหมดสาธิต)

ถ้า `config.js` ยังว่าง ระบบจะทำงานในโหมดสาธิต: ข้อมูลเก็บใน browser เครื่องนั้น และมีข้อมูลจำลองการดำเนินงาน 2 เดือน

- เปิด `index.html` → จองห้อง → แจ้งเลขอ้างอิงการโอน
- เปิด `admin.html` ใน browser เดียวกัน → เลือกพนักงาน → การจองและเงินที่ต้องตรวจจะปรากฏทันที

> ต้องเปิดผ่าน web server (เช่น GitHub Pages หรือ `python -m http.server`) ทั้งสองไฟล์ต้องอยู่โฟลเดอร์เดียวกัน เพื่อให้ใช้ข้อมูลร่วมกัน

## 2. ขึ้นใช้งานจริงด้วย Supabase

> แพ็กเกจนี้เชื่อมกับโปรเจกต์ `tnifwfakyfanqczmlkgi` (องค์กร winterm9624) แล้ว ติดตั้งตาราง ฟังก์ชัน และข้อมูลเริ่มต้นครบ เหลือขั้นตอน 3–5 และ 7–8 ด้านล่าง


1. สร้างโปรเจกต์ Supabase (region `ap-southeast-1` ใกล้ลาวที่สุด)
2. **SQL Editor** → รันไฟล์ตามลำดับ: `sql/01_schema.sql` → `sql/02_functions.sql` → `sql/03_seed.sql`
3. **Authentication → Users → Add user** สร้างบัญชีเจ้าของโรงแรม
4. รันใน SQL Editor (เปลี่ยนอีเมล):
   ```sql
   insert into staff (user_id, name, role)
   select id, 'ชื่อเจ้าของ', 'owner' from auth.users where email = 'owner@your-hotel.la';
   ```
5. ใส่ยอดยกมาจริงของโรงแรม (ดูบล็อกที่ comment ไว้ท้าย `03_seed.sql`)
6. **Project Settings → API** คัดลอก Project URL และ anon public key ใส่ใน `config.js`
7. อัปโหลดทั้งโฟลเดอร์ขึ้น GitHub Pages (หรือ hosting ใดก็ได้)
8. เจ้าของล็อกอิน `admin.html` → ตั้งค่า → เพิ่มพนักงาน (สร้างบัญชีใน Supabase Auth ก่อน แล้วใส่อีเมลเดียวกัน)

ถ้ามี QR รับเงินจริงจากแอปธนาคาร (merchant) ให้ใส่ URL รูปใน `paymentQrImage` ของ `config.js`

## 3. สิทธิ์ตามตำแหน่ง

| ตำแหน่ง | สิทธิ์ |
|---|---|
| เจ้าของ (owner) | ทุกอย่าง + จัดการพนักงาน + ปลดล็อกงวดบัญชี |
| ผู้จัดการ (manager) | การจอง ห้อง ราคา โค้ดส่วนลด บัญชี ยกเลิกรายการในโฟลิโอ |
| พนักงานต้อนรับ (frontdesk) | จอง เช็คอิน/เอาท์ รับเงิน ตรวจเงินโอน ปิดยอดประจำวัน สถานะห้อง |
| นักบัญชี (accountant) | ค่าใช้จ่าย บันทึกบัญชี กลับรายการ VAT ปิดงวด ล็อกงวด ตรวจเงินโอน |
| แม่บ้าน (housekeeping) | สถานะห้องเท่านั้น |

สิทธิ์ถูกบังคับที่ฐานข้อมูล (ฟังก์ชันตรวจตำแหน่ง + Row Level Security) ไม่ได้ซ่อนแค่ปุ่มบนหน้าจอ

## 4. ความถูกต้องและการตรวจสอบย้อนหลัง

- **ลงบัญชีคู่อัตโนมัติ** ทุกการกระทำหน้าโรงแรม (มัดจำ ค่าห้องรายคืน ค่าบริการ รับเงิน OTA ค่าคอม) สร้างรายการบัญชีที่ server เท่านั้น ใช้เกณฑ์คงค้างตาม IFRS
- **เดบิตต้องเท่ากับเครดิต** ฐานข้อมูลปฏิเสธรายการที่ไม่สมดุล
- **แก้ไข/ลบไม่ได้** รายการบัญชี การชำระเงิน และโฟลิโอแก้ไม่ได้ ถ้าผิดต้อง "กลับรายการ" (reversal) หรือ "ยกเลิกรายการ" (void) พร้อมเหตุผล
- **ล็อกงวด** เดือนที่ล็อกแล้วบันทึกเพิ่มไม่ได้ ปลดล็อกได้เฉพาะเจ้าของ และถูกบันทึกในประวัติ
- **บัญชีคุม** 1130 (ลูกหนี้แขก), 1140 (ลูกหนี้ OTA), 2150 (มัดจำ) เปลี่ยนได้ผ่านการจองเท่านั้น และระบบตรวจกระทบยอดกับบัญชีย่อยให้ตลอด
- **ห้ามจองซ้อน** ฐานข้อมูลมี exclusion constraint กันห้องเดียวกันถูกจองคืนเดียวกัน แม้มีคนจองพร้อมกัน
- **ประวัติการใช้งาน (audit log)** บันทึกว่าใครทำอะไร เมื่อไร กับรายการไหน และแก้ไขไม่ได้
- **วันที่ทำการ** เลื่อนได้ผ่าน "ปิดยอดประจำวัน" เท่านั้น

ทดสอบแล้ว 39 กรณีบน PostgreSQL 16 (`tools/test-sql.js` ในแพ็กเกจต้นฉบับ)

## 5. สิ่งที่ยังไม่มี (ควรทำก่อนเปิดใช้จริง)

- **ยืนยันเงินโอนอัตโนมัติ**: ตอนนี้พนักงานตรวจกับบัญชีธนาคารแล้วกดยืนยันเอง ถ้าต้องการอัตโนมัติต้องเชื่อม API ของ BCEL OnePay
- **Channel manager**: ยังไม่เชื่อม Booking.com / Agoda / Expedia พนักงานต้องลงการจอง OTA เอง
- **แจ้งเตือน**: ยังไม่ส่งอีเมล / WhatsApp ยืนยันการจองให้แขก
- **กันสแปมการจอง**: ฟังก์ชันจองสาธารณะยังไม่จำกัดจำนวนครั้ง ควรเพิ่ม rate limit / CAPTCHA ก่อนเปิดสาธารณะ
- **ข้อมูลจำนวนมาก**: หลังบ้านโหลดข้อมูลทั้งหมดครั้งเดียว เหมาะกับโรงแรมขนาดเล็ก-กลาง เมื่อข้อมูลเกิน 1–2 ปีควรแบ่งหน้า
- **ภาษีและบัญชี**: อัตรา VAT และภาษีเงินได้ควรยืนยันกับกรมภาษี / นักบัญชีที่มีใบอนุญาตก่อนยื่นจริง
